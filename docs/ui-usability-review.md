# UI・操作性の改修記録

## 対象

2026年9月8〜9日の改修。番組表、見逃し検索、ライブ、ライブラリ、共通プレーヤーを実装コードから確認し、並行した担当作業を段階的に統合しています。PRを作らず、検証した単位で `main` に反映しています。

## 再生と詳細画面の追加修正

- 詳細画面を開いたままでも、「配信なし」のキャッシュ期限と新しい配信状態を反映します。表示の時計は30秒ごと、操作時の日時・再生対象は実行時に再評価します。
- 番組表詳細の外側の失敗案内、内側プレーヤーの再試行、失敗詳細シート、中断からの再開は、同じ操作所有者が実行時の時計と再生対象を確認します。番組終了後はその放送回の見逃し検索へ進み、別の局・既知の別放送回に変わった後の古い回復操作は実行しません。
- 再生項目を保持した音声セッションの失敗では、最初から解決し直す代わりに既存項目を再開します。
- まだ読み込み中に一時停止してからライブ画面へ戻っても、処理を重複開始したり、勝手に再生を再開したりしません。
- PiPは画面を離れても、実際の開始・停止処理に必要な間だけ保持します。全画面と通常画面のどちらかが閉じても、もう一方の復帰処理を消しません。アプリ側の停止・再生終了では残ったPiPも停止します。
- 背景の単発タップはUIKitがダブルタップを除外してからコントロールを切り替えます。以前の「先に切り替えて後から打ち消す」方式をやめました。この変更は余白への背景タップが対象です。実際の連続タッチの検証範囲は下記の制限を参照してください。

## 大きな文字と操作の継続性

- ライブラリの大きな文字では、分類名を全幅にし、件数と開閉マークを次の行へ配置します。選択中分類の重複見出しも省きます。件数はライト／ダーク双方に追従する不透明な文字色です。
- 番組行の移動先とダウンロード操作は兄弟要素のまま、アクセシビリティ文字サイズでは縦に並びます。サイズ切り替えで操作側の確認状態を作り直さないレイアウトを使います。
- 番組表一覧は各行に放送局名を折り返して表示します。現在位置へ移動して節見出しが画面外になっても、その行の放送局を識別できます。
- グリッドの現在時刻の線は局間の余白だけに描き、半透明の番組カード越しに文字・バッジを横切らないようにしました。
- プレーヤー背景への実タッチ受信時に、表示中コントロールの古い自動非表示期限を取り消します。非表示のコントロールをタッチ受信だけで表示したり、一時停止・操作保持中の非表示抑制を解除したりしません。
- 縦の短い全画面では時間表示の固有サイズを確保します。大きな文字の場合に加え、通常文字でも利用可能な高さが非常に短い横長の全画面では主要操作を上段へまとめます。番組名は設定メニュー、詳しい失敗理由は既存の詳細画面で確認できます。時間の文字サイズ・44ptの操作領域は縮小していません。
- 横長で短い全画面では、シークバーと時間表示を同じ段に配置して高さを節約します。経過時間と残り時間の間には最低8ptの隙間を確保し、数字がつながって見えないようにします。時間の文字サイズ、読み上げ内容、44ptの操作領域は維持します。
- 全画面の映像は端まで広げたまま、その画面が持つセーフエリアを操作部分へ渡します。閉じる操作・シークバー・時間表示が画面端の安全領域へ入り込む条件を修正しました。
- 描画fixtureは正式なホスティングコントローラーの包含と画面へのサイズ提案を使用します。単独のプレーヤーキャンバスと通常画面のセーフエリア扱いを区別します。これは実アプリの全ルート操作の検証ではありません。

## ダウンロードの通信条件

Appleの既存ダウンロードタスクは、作成時の通信設定を後から変更できません。現在のアプリ設定だけを変更しても、既存のWi-Fi専用タスクがモバイル通信可能になるわけではありません。

- 「再開」は途中データを残す操作です。元タスクが失われていても、無断で最初から取り直しません。
- 「今回だけモバイル通信で最初からやり直す」は、途中データの削除を説明した上で実行します。事前条件の確認で失敗した場合は、途中データを維持します。
- 一度の同意でWi-Fi限定設定を恒久的に解除しません。
- 個別の再取得に加え、復旧のお知らせからの一括やり直しも対象・件数・途中データの削除を確認します。同意は一度限りで、実行時に状態が一致する停止・失敗中の対象だけへ適用します。確認中に待機中・転送中・保存済みへ変わった対象や、別の停止状態になった対象は残します。古いお知らせの対象も更新します。
- 再起動前のタスクの通信条件が不明な場合は、安全側に扱います。Wi-Fi接続後の再開、または明示的な最初からの取得が必要になることがあります。

## ダウンロード復元中の操作

- 非同期の準備中に中止・置き換えたタスクを、後から返った準備結果で再開しません。古いタスクの遅延通知を、新しいダウンロードの進捗・保存先と混同しないようにします。
- 復元したタスクはセッションとタスクの両方で識別します。所有者が決まる前に届いた完了・失敗・保存先の通知も、その復元対象と世代が一致する場合だけ反映します。
- 復元一覧を取得する途中で見つかったタスクにも中止・削除を届けます。残りの一覧取得を待ち続けたり、空の保存一覧への復元し直しで中止要求を失ったりしません。重複した制御要求を抑え、古い復元処理の終了時に、新しく採用された同じタスクを停止しません。
- 復元候補を保持しているだけでは再開やモバイル通信を許可しません。途中データを残す再開と、明示的な最初からの取得の区別は維持します。

## 長時間表示の追加回帰（2026年9月9日）

`d25eca2` の表示コードを変えず、実際の `FullScreenPlaybackView` に3時間のローカルWAVを読み込み、一時停止したまま90分の位置へシークする回帰を追加しました。元の7メソッドと全ての既存アサーション、通常fixtureの120秒／75秒の設定は維持しています。

- 最大アクセシビリティ文字サイズ、高さ240pt、幅528／560／640ptで `1:30:00` と `-1:30:00` を検査します。WAVは各172,800,044bytesです。
- 表示用の時刻だけでなく、実AVPlayerの5400秒へのシーク完了と、AVPlayerItemの10800秒の長さを照合します。

## 画面を再生成する

利用可能なSimulatorを `xcrun simctl list devices available` で確認し、対象のUDIDを指定します。

```bash
xcodegen generate
TEST_RUNNER_RECORD_UI_SNAPSHOTS=1 xcodebuild \
  -project TVerClient.xcodeproj \
  -scheme TVerClient \
  -destination "platform=iOS Simulator,id=${SIMULATOR_UDID}" \
  -parallel-testing-enabled NO \
  -only-testing:TVerClientTests/UIRenderingRegressionTests \
  -resultBundlePath /tmp/TVerClient-UIReview.xcresult \
  CODE_SIGNING_ALLOWED=NO test
```

結果はXCTestの添付画像と、アプリコンテナ内の `Documents/UIReviewSnapshots` に保存されます。再実行時は新しいresult bundleのパスを使ってください。

## 継続調査項目

このチェックポイントでは、次の範囲を未検証のまま残しています。実端末で不具合を再現したという意味ではありません。

- 実際のバックグラウンドHLSタスクでの復元・停止遅延・保存データの変化、列挙が返らない場合の解放期限、複数世代の組合せは追加検証が必要です。
- 長時間の時刻文字列は上記の固定3条件を追加検証しました。指を置いたままのシーク中に配置を切り替える条件、VoiceOverの実フォーカス順は未検証です。
- 別々のPiPコーディネーターを伴う画面再入場時のレイヤー継続性は検証候補です。実端末の映像停止・黒画面を再現したという意味ではありません。

## 検証範囲の限界

- 画面fixtureは本物の各SwiftUI画面をホストし、ネットワークを使わないダミー番組・画像なし・仮の保存ファイルを使います。動画デコード、実RootTabの全ライフサイクル、実際のアラート操作や指での連続タップを証明するものではありません。
- 描画成功や44ptの操作領域検査は、全ての視覚・操作上の問題がないことを意味しません。生成画像の視覚レビューは別に行います。
- 日付は実行時からの相対値です。OSをまたぐピクセル完全一致のスナップショット比較ではありません。
- iOS 16の実ランタイム、実端末でのPiP・回転・VoiceOver、日本からの実配信、実際のモバイル通信での保存は別途確認が必要です。
- 地域制限、DRM、広告SDK、認証などのアクセス条件を回避する処理は追加していません。
